# Исходящий прокси (outbound proxy)

Позволяет прокси-серверу выходить в интернет **через сторонний прокси** (SOCKS5 или HTTP/HTTPS CONNECT). Клиент (Telegram Desktop) по-прежнему подключается к локальному прокси как обычно (`127.0.0.1:1443`) — исходящий прокси влияет только на то, как сам прокси-сервер соединяется с Telegram и Cloudflare.

## Когда это нужно

- Прокси-сервер запущен в сети **без прямого выхода** в интернет (выход только через корпоративный/промежуточный прокси).
- Сеть требует **маршрутизации/аутентификации** через прокси для любых внешних соединений.
- Нужно пустить весь трафик прокси-сервера через определённую точку выхода.

> [!NOTE]
> Исходящий прокси маршрутизирует соединения прокси-сервера, но **не меняет шифрование**: данные между клиентом и Telegram остаются в зашифрованном MTProto. Прокси видит только факт туннеля (`CONNECT` к `IP:443` для HTTP или SOCKS-трафик), а не содержимое.
>
> Эта настройка **не является сама по себе обходом инспекции по SNI/домену**: если промежуточный узел блокирует соединения по SNI `*.telegram.org`, исходящий прокси не поможет.

## Как это работает

Когда исходящий прокси задан, **все** исходящие соединения прокси-сервера идут через него — в том числе фоновый пул предварительных соединений:

- **WSS-соединения** (TLS + WebSocket) к датацентрам Telegram по доменам `*.web.telegram.org` — основной путь;
- TCP-fallback к датацентрам Telegram;
- соединения через Cloudflare Worker и Cloudflare Proxy.

Это обеспечивается единой точкой установки соединения (`RawWebSocket.connect` и TCP-fallback): при наличии прокси сначала устанавливается туннель до прокси (`SOCKS5` или `HTTP CONNECT`), затем поверх него — TLS-соединение с целью (для WSS — с тем же SNI, что и при прямом подключении). При отсутствии прокси соединение идёт напрямую.

## Настройка через GUI

В окне настроек откройте секцию **«Исходящий прокси»**:

| Поле | Описание |
|---|---|
| **Тип** | `socks5`, `http` или пусто (пусто = прокси выключен) |
| **Host** | Адрес исходящего прокси |
| **Port** | Порт исходящего прокси |
| **Логин** | Имя пользователя для аутентификации (необязательно) |
| **Пароль** | Пароль для аутентификации (необязательно) |

Значения сохраняются в конфигурации вместе с остальными настройками. Чтобы выключить прокси — оставьте поле **Тип** пустым.

### Кнопка «Тест»

Кнопка проверяет, что указанный прокси реально пропускает трафик к Telegram: прокси-сервер выполняет то же самое соединение, что и в боевом режиме (`SOCKS5`/`HTTP CONNECT` к IP датацентра Telegram на порт `443`), и показывает результат.

Возможные результаты:

- **✓ работает** — прокси пропустил соединение; боевой трафик через него пойдёт.
- **таймаут** — прокси не ответил.
- **ошибка логина/пароля** — неверные учётные данные аутентификации на прокси.
- **прокси не пустил к Telegram** — прокси ответил, но отказал в соединении с целью.
- **недоступен** — к прокси невозможно подключиться.

> [!IMPORTANT]
> Тест использует те же IP датацентров и тот же механизм соединения, что и рабочий трафик. Результат теста показывает прокси "пригоден" / "не пригоден".
